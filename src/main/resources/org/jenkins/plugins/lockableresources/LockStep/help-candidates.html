Optional list of resource names to lock from, in list order. Use exactly one of resource, label or candidates.

  • Without quantity: all listed resources are locked, like a list of named resources. A resource that does not exist is created as an ephemeral resource when ephemeral resources are allowed; otherwise it is skipped with a line in the build log. If none of the listed resources exist then, the step fails. In a group other than common every listed resource must exist, as for resource.
  • With quantity: only resources that exist are used. They are tried in list order and the first free ones are locked (the random strategy shuffles the list first). Names that do not exist are skipped with one line in the build log. If fewer resources exist than requested, the step fails when "fail fast on insufficient resources" is enabled, and waits otherwise.
  • With group, only candidates of that group are used.
  • The list is checked again each time the queue is processed: a resource deleted while waiting is no longer a candidate.

Use findLockableResources to build the list, for example: 

def preferred = findLockableResources(label: 'os:Debian && nwcard:1').findAll { r -> !r.description.contains('Test-agent') }
def sorted = preferred.findAll { r -> r.labels.contains('nwcard:2') } + preferred.findAll { r -> !r.labels.contains('nwcard:2') }
lock(candidates: sorted*.name, quantity: 2, variable: 'LOCKED') { echo 'Locked: ' + env.LOCKED }

candidates is not available in the Snippet Generator form, because a text field cannot hold a list. Write it in the Pipeline script directly. It is not supported for remote locks (serverId): such a lock fails with an error.
