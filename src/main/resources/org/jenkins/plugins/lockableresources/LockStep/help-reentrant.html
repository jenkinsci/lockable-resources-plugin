By default a nested lock on a resource that an enclosing lock of the same build already holds waits forever, because the build waits for itself.

By checking this option the body runs right away when every requested resource is already held by an enclosing lock block (including options { lock(...) } in a declarative pipeline). Nothing is released when this inner block ends; the enclosing block still owns the resources.

If only some of the resources are held, the step waits for the others as usual. Parallel branches that are not inside an enclosing lock still wait for each other. Only named resources are supported; label requests are always locked as usual.
