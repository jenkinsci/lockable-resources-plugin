Maintenance switch for the remote lock API. Leave it on for normal operation.

While it is off, this controller answers POST /lockable-resources/remote/v1/acquire with 503 and the error code ACQUIRES_PAUSED, so no new remote lock is handed out. Everything else keeps working: leases already held can send heartbeats and release normally, status can still be polled, and requests already waiting in the queue keep their place and are still promoted as resources free up.

Client controllers do not fail their builds when they see this. They keep retrying until their own allocation timeout expires, so you can drain this controller for maintenance without disturbing the pipelines waiting on it.
